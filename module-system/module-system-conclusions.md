# 模块系统讨论总结 (2026-08-10 会话)

> 用途: 防止上下文压缩导致结论丢失。用户检查确认后, 已同步写入 `module-system/design.md` (v0.8)。
> 本文件是"模块拆分机制"专项讨论的结论存档。

## 一、include 关闭

不再引入 include 机制。模块拆分由 **平等模块 + `use inner`** 解决, 不引入文件合并语义。

## 二、程序 = 包 = 模块 (统一组织单位)

两种组织形态:

**单文件脚本** (小项目/快速脚本)

```
project.ns
```

- 只能 use `modules/` 里的模块; **没有 inner** (写 inner 报错, 它不是包)

**包** (大项目 / 模块)

```
mylib/                      # 包根 (包名 = mylib)
├── mylib/
│   └── mylib.ns            # 主脚本, 必须与包名同名
└── helpers/
    └── helpers.ns          # 包内子模块, 用 use inner 引用
```

- 包根在**项目根** = 程序 (执行 `mylib/mylib.ns`)
- 整个包搬进 `modules/{来源}/` = 模块 (`use mylib from custom` 加载同一个主脚本) —— 零代码改动

## 三、目录结构 (三层)

`modules/{来源}/{包}/{模块}/{模块}.ns`

- 定位: `use x from S` → `modules/S/x/x/x.ns` (包名 = 模块名 = 主脚本名)
- `use inner x` → `当前包根/x/x.ns` (当前文件所在包的内部模块)
- 包内子模块对包外不可见 (`use x from S` 定位不到包内的 x), 想公开就平铺成独立包

## 四、use inner 语法

```
use inner x [as z]     # 无 from; 写了 from 报错
```

- 仅存在于"包内文件" (包主脚本、包内子模块都可以用)
- inner 的定位由当前文件位置决定 (当前包根), 不需要 from

## 五、cmdargs / debug 新规则

- **cmdargs**: 只对**入口文件** (被解释器直接执行的文件) 生效。非入口文件 (被 use 的模块) 写了**不报错、不生效**, 参数保持默认值。模块作者两手准备: 作入口收命令行参数, 被 use 靠 API 传参
- **debug**: 入口文件的 debug 声明生效; 命令行 `--debug` 优先级最高; 非入口文件写了不生效、不报错

## 六、autoinit 块

```
debug N
modules ... endmodules      # 可选
cmdargs ... endcmdargs      # 可选
autoinit                    # 可选: 加载时自动执行的初始化代码块
# 可执行语句 (初始化动作)
endautoinit
<主逻辑(顶层语句)>
```

**两种加载路径**:

| 路径 | autoinit 块 | 顶层语句 (主逻辑) |
|---|---|---|
| 程序入口 (直接执行) | 执行 | 执行 |
| 模块加载 (被 use) | 执行 | **不执行** |

- 块内只允许可执行语句 + 注释 (`global` 声明、函数定义在顶层, 加载时建立)
- 全文件至多一个, 放头部区 (与 modules/cmdargs 同级)
- **项目 → 模块迁移**: 主逻辑组织成函数, 顶层只留一句 `call 主逻辑()` —— 作程序时顶层跑 (启动); 作模块时顶层不跑, 调用方 `call 模块.主逻辑()` 手动启动
