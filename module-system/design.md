## 1. 目标与定位

| 项 | 说明 |
|---|---|
| 目的 | 代码复用: 工具函数库、数据结构库, 以 NS 自身编写 |
| 场景 | canvas 游戏引擎驱动脚本、嵌入式脚本、教学 |
| 原则 | 设计一次成熟再开工; 避免技术债导致大面积重构 |
| 对外契约 | `NSI` 现有接口 (`run` / `runInteractive` / `setInput` / `setLanguage` 等) 不变; 模块是**新增能力**, 不改变既有语义 |

## 2. 语法

### 2.1 `use` 语句

```
use xxx          # 加载 modules/xxx.ns, 模块对象名 = xxx
use xxx as yyy   # 加载 modules/xxx.ns, 模块对象名 = yyy
```

- `use` 仅允许出现在头部 `modules ... endmodules` 块内 (见 §2.3), 主内容区 `use` 报错
- 模块对象名 = 文件名 (不带 `.ns` 后缀)
- `as` 用于重命名 (解决同名模块间引用歧义)

### 2.3 文件头部区结构 (显式模块块)

```
debug N              # 可选: 物理首行, 命令行 --debug 显式指定时忽略 (沿用现有优先级)
modules              # 模块块开始 (可选, 无模块需求时整个块省略)
use xxx
use yyy as z
endmodules           # 模块块结束
<主内容...>
```

规则:

- 全文件**至多一个** `modules` 块, 必须位于头部 (debug 之后或文件开头); `endmodules` 之后再用 `modules` 报错 (保持 "use 必须开头" 的意图)
- 块内**只允许** `use` 语句 + 空行 + 注释; 其他语句报 "模块块内只允许 use 语句"
- 未闭合检测: 有 `modules` 无 `endmodules`、或裸 `endmodules` → 语法错误 (复用现有块配对机制)
- 主内容区出现 `use` → 报错 (use 只能在模块块内)
- `modules` / `endmodules` 为保留字 (NS 保留字本就禁止作变量名, 代价小)
- 无模块需求时整个块可省略, 文件与现有版本完全兼容
- 模块文件头部同样适用 (模块文件可含 `debug` + 模块块; 嵌套 `use` 见 §3.1)

### 2.2 幂等与冲突

- **同一文件内**同一模块只能 `use` 一次 (含别名: `use a` 与 `use a as x` 视为同一模块), 重复 → 语法错误 "重复 use 模块 a"; 一个模块在同一文件内只有一个名字, 杜绝别名多命名
- **跨文件幂等**: 模块实例全局唯一, 全项目依赖图中每个模块只加载一次 (主程序与多个模块引用同一模块时共享实例)
- `as` 的真实用途 (单一 `modules/` 目录下文件名唯一, 不存在"两文件撞同名"):
  1. **短名别名** (便利性)
  2. **避让与主脚本命名冲突**: 模块对象名可能与主脚本全局变量/函数同名 (`global stack` 与 `use stack`), 用 `use stack as stk` 改名避让
  3. **未来多来源消歧 (预留)**: 模块管理器引入内置/第三方/宿主注入模块后可能出现真实同名, `as` 承担消歧
- 不同模块被 `use` 成同一对象名 (`use a as x` + `use b as x`) → 编译期报错 (命名冲突)

## 3. 模块文件

位置: `modules/xxx.ns`, 与解释器同目录。模块文件是普通 NS 文件, 顶层内容:

| 顶层内容 | 语义 |
|---|---|
| `global` 声明 | 模块私有变量 (仅模块内可访问) |
| `:func ... :end` 定义 | 模块导出成员, 挂到模块命名空间对象 |
| 可执行语句 | 加载时执行一次 (初始化); 输出强制带 `[模块 xxx]` 来源标识 |
| `modules ... endmodules` 块 (可选) | 嵌套 `use`: 声明本模块的依赖 (见 §3.1) |

### 3.1 嵌套 use (模块依赖)

- 模块文件头部语法与主程序完全一致: 可选 `debug` + `modules ... endmodules` 块
- **递归加载**: 主程序 `use A` → A 头部 `use B` → 先加载 B 再加载 A
- **跨文件幂等**: 全项目依赖图中每个模块只加载一次 (见 §2.2)
- **循环检测**: A → B → A 报语法错误 "模块依赖循环"
- **封装**: A use 的 B 只在 A 的文件作用域内可见 (A 的函数体内可调 `B.func`), **对主程序/其他模块不可见** —— 依赖不泄漏; A 的命名空间对象只含 A 自身导出的成员

- 模块函数体: 与普通函数体一致 (局部变量/数组/错误处理/try-catch 全部照常), 且走 NSVM 函数调用管道

## 4. 命名空间与作用域

- 模块符号挂**模块命名空间对象**, **不进全局函数表** → 与主脚本全局/函数零冲突, 无需改名
- 模块函数内变量查找链 (固定两跳):

```
局部变量 → 模块私有全局 → 未声明报错
```

- `global.` 前缀在模块内 = **强制访问模块私有全局** (块级作用域局部遮蔽时使用), 语义与主脚本内 `global.` 强制访问全局对称
- 模块函数内不可声明全局 (与现有"函数内不可声明全局"规则一致)
- 模块是**黑盒**: 不读不写主脚本任何变量, 与主脚本交互只有"实参进 + 返回值出"

## 5. 调用形态 (单入口: call 是函数专用)

**函数 (用户/模块) 只有一条调用路径: `call` 语句。表达式不调用函数** —— 表达式里出现的 `Math.*`/`String.*`/`Bit.*`/`len` 等是**词法内置对象**, 与运算符 (`+` `-` 等) 同级, 不是"函数" (详见 §5.1)。

| 形态 | 示例 | 路径 |
|---|---|---|
| 语句 | `call tools.min(a, b) -> y` | `executeCall` 名字解析扩展模块前缀 → 同一调用管道 |

模块函数与普通函数共用同一调用管道 → 函数体编译为指令 (NSVM), 不牺牲性能。

> 语句入口前置 (2.7.1 已落地): `executeCall` 正则已扩展支持点分函数名, 并设内置函数快速通道 (`String.split` 定长容器填充所用, 见 doc.md "内置函数"); 模块函数语句入口复用同一通道。NSVM 编译 CALL 正则不含点分 → 含点分名的 call 语句整体回退行解释器, 零 NSVM 改动。

### 5.1 词法能力 vs 过程 (分层定位)

**语言能力分两层, 调用形态由层级决定, 不重叠:**

| 层级 | 成员 | 调用形态 |
|---|---|---|
| 词法能力 (与运算符同级) | Math.* / String.* / Bit.* / len 等内置对象 | 表达式 `y = Math.min(a, b)` (可嵌套运算) |
| 过程 (函数) | 普通用户函数 / 模块函数 | 只能 `call f(a) -> y` 语句 |

- **函数单入口 (定稿)**: 用户函数与模块函数统一走 `call`, 无"表达式/语句"双写法; `call` 的功能不被削弱 —— 动作、数组容器填充、`mut` 写穿、数组返回值、void 全部由 `call` 承载, 表达式本就不承担这些
- **定位依据**: Math 之类是**解释器内置能力**, 跟运算符一样是词法的 (作者原话: "math 之类的定位就是内置函数跟运算符统一级别"); 函数是程序的过程抽象, 与 `if`/`for` 同级, 用语句调用
- **同形不变**: §6 的"名字.函数()"在 call 语句下依然成立 (`call tools.min()` / `call injected.obj()`), JS 注入对象与 NS 模块写法无差别
- 代价 (已接受): `y = tools.min(a, b) + 1` 的嵌套写法不可用, 需先 `call` 到中间变量再运算 —— 符合"函数调用是语句"的语言风格
- 与历史一致: 语言自始不支持用户函数进表达式 (表达式里报"未知函数"), 本定稿只是把该现状确认为设计, 而非缺陷

## 6. JS 能力分层 (与宿主桥接合流)

```
语法层 (模块书写语言)  →  只用 NS, 统一
能力层 (谁能提供函数)  →  NS 模块 + registerGlobal 注入的 JS 对象, 都行
```

- JS 注入对象与 NS 模块在 NS 代码中**同形**: 都是 `名字.函数()`, 脚本作者无感知
- 值互通 (NS 值底层即 JS 值):

| NS 类型 | 底层真身 | JS 侧 |
|---|---|---|
| int / float / number | `number` | 数字 |
| string | `string` | 字符串 |
| array | `Array` | 数组 |
| bool | `boolean` | 布尔 |

- 约束: 注入对象返回值限于上述四类; 返回对象/函数等视为非法值并报错

## 7. 加载机制 (框架, 细节待定)

- 加载器可注入: `NSI.setModuleLoader(name => 源码字符串)`
- Node/CLI 默认: `fs` 读取 `modules/{name}.ns`
- 浏览器: 由宿主提供 loader (嵌入式场景刚需, 与 §6 宿主桥接方向衔接)
- 触发时机: 加载期头部区解析 (见 §2.3), 先于 NSVM 编译与主程序执行
- 加载失败 (找不到文件/语法错误): 错误信息标注模块名
- 循环 `use` (A → B → A): 检测并报错
- 模块内动作输出强制带模块名标识 (见 §3)

## 8. 动态结构约定 (元数据槽模式)

> 状态: **已确认** (确认记录 #16)。原"数组动态化"待定项结论定论: **不实施语言级动态数组**。

- 结论依据: 动态长度结构 (栈/队列/集合等) 可由**定长数组 + 显式状态**完全承载, 无需语言级"有界动态"机制; 语言保持"静态/显式/可预测"初衷, 核心零改动, 保住 24/24 逐字节回归红线
- 模式: **元数据槽** —— 数组 `st[0]` 存逻辑状态 (如栈顶下标, 空栈=0), 数据从 `st[1]` 起, 数据容量 = `len(st) - 1` (容量由声明方决定, 使用者用 `len(st)` 动态读取, 不写死); 越界 (空栈 pop / 满栈 push) 用 `assert` 显式报错不静默
- 栈顶为何不能用显式 int 引用: `mut` 关键字仅对数组参数有效, int 无引用传递 → 元数据槽是唯一正解
- 覆盖边界: 元数据槽覆盖**单层动态结构** (栈/队列/集合/池); 嵌套引用结构 (树/图/链表) 需元素存引用, 而数组元素为标量值存不了数组引用 —— 这属"引用类型"问题, 与动态数组无关 (动态数组元素同样存不了引用), 故动态数组两头都不占, 确认关闭
- 栈模块示例 (按 2.7.0 数组形参元素类型语法验证可运行, 含 `st[st[0]]` 嵌套下标 / assert 块 / mut 匹配规则):

```ns
// modules/stack.ns — 定长栈模块 (元数据槽模式)
// 栈数组由调用方声明传入: st[0] 存栈顶下标 (空栈=0), 数据从 st[1] 起
:newStack (mut st[]:int) -> :void
st[0] = 0
:end

:push (mut st[]:int, v:int) -> :void
assert (st[0] < len(st) - 1)
"栈已满: 容量 " + (len(st) - 1)
endasrt
st[0] = st[0] + 1
st[st[0]] = v
:end

:pop (mut st[]:int) -> v:int
assert (st[0] > 0)
"栈为空"
endasrt
v = st[st[0]]
st[0] = st[0] - 1
return v
:end

:peek (st[]:int) -> v:int
assert (st[0] > 0)
"栈为空"
endasrt
v = st[st[0]]
return v
:end

:size (st[]:int) -> n:int
n = st[0]
return n
:end

:isEmpty (st[]:int) -> r:bool
r = (st[0] == 0)
return r
:end
```

```ns
// 调用方 (主脚本) — use 必须位于头部 modules...endmodules 块内 (§2.3);
// push/pop 形参 mut, 实参须带 mut; peek/size/isEmpty 只读, 实参不带 mut
modules
use stack
endmodules

global array st[6]:int = arrfill
call stack.newStack(mut st)
call stack.push(mut st, 10)
call stack.push(mut st, 20)
call stack.pop(mut st) -> v
call stack.size(st) -> n
```

### 8.1 嵌套引用结构 (对象池 / 平行数组句柄)

- 链表/树/图等嵌套引用结构: 数组元素为标量值, 无引用类型, 亦不允许"数组的数组"; 用**平行数组 + 整数索引句柄**承载 (对象池模式), 与 C 语言"数组模拟指针"同构
- 模式: 节点池由 N 个平行定长数组表示 (值 / 左子 / 右子 / 空闲链各一数组), 节点身份 = 数组下标 (句柄), `-1` = 空引用; 空闲节点用空闲链维护 (alloc/free)
- 已验证: 单链表 push-front / 遍历 / 空闲池分配实际运行通过 (含 `node_next[free_head]` 句柄链)
- 多维数组: 一维数组 + 下标计算 (`matrix[1 * COLS + 2]`), 见 doc.md "多维数组实现"
- 键值映射: 平行 key/value 数组 + 线性查找 (O(n)); 哈希表需 `registerGlobal` 桥接

### 8.2 能力边界 (无论如何实现不了)

| 能力 | 状态 | 说明 |
|---|---|---|
| 函数作为值 (回调/高阶/函数指针) | **实现不了** | 函数不能赋值给变量、不能作实参传递; 排序比较器/事件回调等无表达路径 |
| 泛型 | **实现不了** | 类型显式声明, 无类型参数机制; 栈模块须按元素类型复制 (显式语言可接受的取舍) |
| 字符串处理 (子串/分割/查找/正则) | 已内置 | 2.7.1 起 `String.*` 内置 (长度/子串/查找/大小写/替换/去空白); 正则仍需 `registerGlobal` 桥接 JS |
| 位运算 (& / \| / ^ / << / >>) | 已内置 | 2.7.1 起 `Bit.*` 内置 (32 位有符号); NS 运算符语法仍不动, 以函数形式提供 |
| 运行时反射 / 动态类型 | 实现不了 | 静态显式语言, 无运行时类型信息查询 |

## 9. 待定事项 (未并入正式章节)

### 9.1 模块管理器

- 动机: 嵌套 `use` (依赖图/版本/安装) 职责不应压在核心解释器上
- 方向: **核心只留最小加载原语** (按名加载 + 挂命名空间 + 依赖图幂等与循环检测); 版本/安装交由"模块管理器模块" (NS 逻辑 + `registerGlobal` 注入的 fs/http 能力), 管理器本身是模块 → 也是最完整的示例
- 类比: 核心如操作系统提供加载原语, 包管理器是用户态程序
