### v0.1 讨论确认记录

| # | 议题 | 结论 |
|---|---|---|
| 1 | 模块书写语言 | 模块**只用 NS 写**; JS 能力走 `registerGlobal(name, obj)` 宿主注入, **不提供 JS 模块文件** (避免双加载管道/双错误边界/双类型系统) |
| 2 | JS 值互通 | NS 值底层即 JS 值 (number/string/array/bool 同源), 注入对象返回值限这四类, 其余视为非法值; 互通零转换成本 |
| 3 | 命名即对象名 | `use xxx` → 模块对象名 `xxx` (= 文件名); `use xxx as yyy` → 对象名 `yyy` |
| 4 | 免配置文件 | `use` 语句即激活声明, 不维护额外模块配置文件 |
| 5 | 符号归属 | 模块符号挂**模块命名空间对象**, 不进全局函数表, 与主脚本全局零冲突 |
| 6 | 模块自包含 (黑盒) | 模块函数内查找链: **局部变量 → 模块私有全局 → 未声明报错**; 不访问主脚本任何全局; `global.` 前缀在模块内指模块私有全局 |
| 7 | 模块与主脚本交互 | 唯一通道: 调用 `xxx.函数(实参)` + 返回值; 模块函数不能读写主脚本全局 (含 `global.` 前缀也不可及) |
| 8 | 调用形态 | 表达式 `y = xxx.func(a)` 与语句 `call xxx.func(a) -> r` 双入口, 共用函数调用管道 → 函数体天然吃 NSVM 指令化 |
| 9 | 加载器可注入 | `setModuleLoader(name => 源码字符串)`; Node 默认 `fs` 读 `modules/`, 浏览器由宿主注入 (嵌入式刚需) |
| 10 | 模块内顶层动作 | 允许顶层可执行语句 (加载时执行一次); **执行时强制在输出前标识来源模块名**, 不依赖编写者自觉 |
| 11 | 嵌套 `use` | 正式设计: 模块文件头部可有模块块 (依赖), 递归加载 + 跨文件幂等 + 循环检测 + 依赖封装 (见 §3.1) |
| 12 | 首版范围 | 不先行锁定"纯函数工具库"范围 —— 数组动态化 (§8.1) 设计成熟后再定, 避免"老写法/新写法"模块版本分裂 (技术债) |
| 13 | `use` 位置 | **文件头部连续块**: 文件以 `debug N` 开头时紧跟其后, 否则从第一行起; 主内容区出现 `use` 报错; 头部区在加载期一次性处理, 先于 NSVM 编译 |
| 14 | 显式界定 | 用 `modules ... endmodules` 块显式划分头部区 (替代隐式扫描"实质性行"); 块内只允许 `use` + 空行 + 注释; 全文件至多一个且必须在头部; 无模块需求时可整体省略 (见 §2.3) |
| 15 | 同文件唯一命名与 `as` 用途 | 同一文件内一个模块只能 `use` 一次 (含别名), 重复报语法错误; `as` 用途 = 短名别名 + 避让与主脚本命名冲突 + 未来多来源消歧 (单一 modules/ 目录下不存在"两文件撞同名"); 跨文件幂等: 模块实例全局唯一 (见 §2.2) |

## 1. 目标与定位

| 项 | 说明 |
|---|---|
| 目的 | 代码复用: 工具函数库、数据结构库, 以 NS 自身编写 |
| 场景 | canvas 游戏引擎驱动脚本、嵌入式脚本、教学 |
| 原则 | 设计一次成熟再开工; 避免技术债导致大面积重构 |
| 对外契约 | `NSI` 现有接口 (`run` / `runInteractive` / `setInput` / `setLanguage` 等) 不变; 模块是**新增能力**, 不改变既有语义 |

## 2. 语法

### 2.1 `use` 语句

```
use xxx          # 加载 modules/xxx.ns, 模块对象名 = xxx
use xxx as yyy   # 加载 modules/xxx.ns, 模块对象名 = yyy
```

- `use` 仅允许出现在头部 `modules ... endmodules` 块内 (见 §2.3), 主内容区 `use` 报错
- 模块对象名 = 文件名 (不带 `.ns` 后缀)
- `as` 用于重命名 (解决同名模块间引用歧义)

### 2.3 文件头部区结构 (显式模块块)

```
debug N              # 可选: 物理首行, 命令行 --debug 显式指定时忽略 (沿用现有优先级)
modules              # 模块块开始 (可选, 无模块需求时整个块省略)
use xxx
use yyy as z
endmodules           # 模块块结束
<主内容...>
```

规则:

- 全文件**至多一个** `modules` 块, 必须位于头部 (debug 之后或文件开头); `endmodules` 之后再用 `modules` 报错 (保持 "use 必须开头" 的意图)
- 块内**只允许** `use` 语句 + 空行 + 注释; 其他语句报 "模块块内只允许 use 语句"
- 未闭合检测: 有 `modules` 无 `endmodules`、或裸 `endmodules` → 语法错误 (复用现有块配对机制)
- 主内容区出现 `use` → 报错 (use 只能在模块块内)
- `modules` / `endmodules` 为保留字 (NS 保留字本就禁止作变量名, 代价小)
- 无模块需求时整个块可省略, 文件与现有版本完全兼容
- 模块文件头部同样适用 (模块文件可含 `debug` + 模块块; 嵌套 `use` 见 §3.1)

### 2.2 幂等与冲突

- **同一文件内**同一模块只能 `use` 一次 (含别名: `use a` 与 `use a as x` 视为同一模块), 重复 → 语法错误 "重复 use 模块 a"; 一个模块在同一文件内只有一个名字, 杜绝别名多命名
- **跨文件幂等**: 模块实例全局唯一, 全项目依赖图中每个模块只加载一次 (主程序与多个模块引用同一模块时共享实例)
- `as` 的真实用途 (单一 `modules/` 目录下文件名唯一, 不存在"两文件撞同名"):
  1. **短名别名** (便利性)
  2. **避让与主脚本命名冲突**: 模块对象名可能与主脚本全局变量/函数同名 (`global stack` 与 `use stack`), 用 `use stack as stk` 改名避让
  3. **未来多来源消歧 (预留)**: 模块管理器引入内置/第三方/宿主注入模块后可能出现真实同名, `as` 承担消歧
- 不同模块被 `use` 成同一对象名 (`use a as x` + `use b as x`) → 编译期报错 (命名冲突)

## 3. 模块文件

位置: `modules/xxx.ns`, 与解释器同目录。模块文件是普通 NS 文件, 顶层内容:

| 顶层内容 | 语义 |
|---|---|
| `global` 声明 | 模块私有变量 (仅模块内可访问) |
| `:func ... :end` 定义 | 模块导出成员, 挂到模块命名空间对象 |
| 可执行语句 | 加载时执行一次 (初始化); 输出强制带 `[模块 xxx]` 来源标识 |
| `modules ... endmodules` 块 (可选) | 嵌套 `use`: 声明本模块的依赖 (见 §3.1) |

### 3.1 嵌套 use (模块依赖)

- 模块文件头部语法与主程序完全一致: 可选 `debug` + `modules ... endmodules` 块
- **递归加载**: 主程序 `use A` → A 头部 `use B` → 先加载 B 再加载 A
- **跨文件幂等**: 全项目依赖图中每个模块只加载一次 (见 §2.2)
- **循环检测**: A → B → A 报语法错误 "模块依赖循环"
- **封装**: A use 的 B 只在 A 的文件作用域内可见 (A 的函数体内可调 `B.func`), **对主程序/其他模块不可见** —— 依赖不泄漏; A 的命名空间对象只含 A 自身导出的成员

- 模块函数体: 与普通函数体一致 (局部变量/数组/错误处理/try-catch 全部照常), 且走 NSVM 函数调用管道

## 4. 命名空间与作用域

- 模块符号挂**模块命名空间对象**, **不进全局函数表** → 与主脚本全局/函数零冲突, 无需改名
- 模块函数内变量查找链 (固定两跳):

```
局部变量 → 模块私有全局 → 未声明报错
```

- `global.` 前缀在模块内 = **强制访问模块私有全局** (块级作用域局部遮蔽时使用), 语义与主脚本内 `global.` 强制访问全局对称
- 模块函数内不可声明全局 (与现有"函数内不可声明全局"规则一致)
- 模块是**黑盒**: 不读不写主脚本任何变量, 与主脚本交互只有"实参进 + 返回值出"

## 5. 调用形态 (双入口)

| 形态 | 示例 | 路径 |
|---|---|---|
| 表达式 | `y = tools.min(a, b)` | 表达式求值器点分标识符分发 → 模块命名空间查函数 |
| 语句 | `call tools.min(a, b) -> y` | `executeCall` 名字解析扩展模块前缀 → 同一调用管道 |

模块函数与普通函数共用同一调用管道 → 函数体编译为指令 (NSVM), 不牺牲性能。

## 6. JS 能力分层 (与宿主桥接合流)

```
语法层 (模块书写语言)  →  只用 NS, 统一
能力层 (谁能提供函数)  →  NS 模块 + registerGlobal 注入的 JS 对象, 都行
```

- JS 注入对象与 NS 模块在 NS 代码中**同形**: 都是 `名字.函数()`, 脚本作者无感知
- 值互通 (NS 值底层即 JS 值):

| NS 类型 | 底层真身 | JS 侧 |
|---|---|---|
| int / float / number | `number` | 数字 |
| string | `string` | 字符串 |
| array | `Array` | 数组 |
| bool | `boolean` | 布尔 |

- 约束: 注入对象返回值限于上述四类; 返回对象/函数等视为非法值并报错

## 7. 加载机制 (框架, 细节待定)

- 加载器可注入: `NSI.setModuleLoader(name => 源码字符串)`
- Node/CLI 默认: `fs` 读取 `modules/{name}.ns`
- 浏览器: 由宿主提供 loader (嵌入式场景刚需, 与 §6 宿主桥接方向衔接)
- 触发时机: 加载期头部区解析 (见 §2.3), 先于 NSVM 编译与主程序执行
- 加载失败 (找不到文件/语法错误): 错误信息标注模块名
- 循环 `use` (A → B → A): 检测并报错
- 模块内动作输出强制带模块名标识 (见 §3)

## 8. 待定事项 (未并入正式章节)

### 8.1 数组动态化

- 结论 (倾向): **确认不实施数组动态化** —— "有界动态" (运行期长度由语言管理) 仍降低可预测性, 违背语言"静态/显式/可预测"初衷; 动态长度结构由**定长数组 + 显式状态**承担, 核心零改动, 保住 24/24 逐字节回归红线
- 模式: **元数据槽** —— 数组 `st[0]` 存栈顶下标 (空栈=0), 数据从 `st[1]` 起, 数据容量 = `len(st) - 1` (容量由主脚本声明决定, 模块用 `len(st)` 动态读取, 不写死); 空栈 pop / 满栈 push 用 `assert` 显式报错不静默
- 栈顶为何不能用显式 int 引用: `mut` 关键字仅对数组参数有效, int 无引用传递 → 元数据槽是唯一正解
- 待确认: 元数据槽模式作为模块书写规范是否最终认可 (示例见 §8.1 上文); 确认后确认记录 #12"首版范围"即自然解封 (无动态化限制, 栈/队列等都能写)

### 8.2 模块管理器

- 动机: 嵌套 `use` (依赖图/版本/安装) 职责不应压在核心解释器上
- 方向: **核心只留最小加载原语** (按名加载 + 挂命名空间 + 依赖图幂等与循环检测); 版本/安装交由"模块管理器模块" (NS 逻辑 + `registerGlobal` 注入的 fs/http 能力), 管理器本身是模块 → 也是最完整的示例
- 类比: 核心如操作系统提供加载原语, 包管理器是用户态程序
